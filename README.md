# Chinese-Laws

中国法律规范文本的公开数据镜像，提供便于阅读的 Markdown、轻量 SQLite
索引，以及版本日期和废止关系元数据。

本仓库不仅收录现行文本，也保留部分历史版本、已修改和已废止文本。它适合
全文检索、法律数据处理、版本研究和学习参考，但不替代国家机关发布的正式
文本，也不构成法律意见。

## 收录范围

- 宪法、宪法相关法；
- 刑事、民商事、经济、社会、行政、生态环境、诉讼程序等法律；
- 行政法规、监察法规；
- 部门规章；
- 地方性法规和地方政府规章；
- 司法解释、法律解释及部分规范性司法文件；
- 国际公法、国际私法、国际经济法相关文本；
- 最高人民法院、最高人民检察院指导性案例。

法律规范主要按效力层级和领域存放。部门规章继续按制定机关细分，地方法规
按省级行政区细分；`地方法规/待分类/` 保存尚待确认地域归属的条目。

`指导案例/` 是仓库既有的独立公开内容，不属于法律文本自动镜像的覆盖范围。

## 文件和版本

每个法律规范版本通常对应一个 Markdown 文件：

```text
<法规标题>(<文本日期>).md
```

同一标题存在多个日期文件时，表示本仓库保存了多个文本版本。文件名中的日期
是版本识别用的“文本日期”，可能来自公布、修订、决定或既有来源日期；它本身
不等于施行日期，也不能单独证明某日仍然有效。

判断时效性时，应结合正文、施行和废止条款以及 `metadata/` 中的证据字段。
如果状态、施行日期或失效日期为空，表示目前没有足够证据确认，不应自行推定。

## 结构化元数据

### `metadata/document_dates.jsonl`

逐文件记录：

- 稳定文档标识、标题、分类和相对路径；
- 文本日期及其依据；
- 公布、通过、批准、修订、施行和失效日期；
- 效力状态、置信度和原文证据。

其中 `relative_path` 可直接定位本仓库中的 Markdown。`source_path` 是构建环境
中的溯源路径，外部程序不应依赖它。

### `metadata/curated_repeal_relations.jsonl`

保存经过核验的废止关系，包括废止文件、被废止文件、生效日期、证据来源、
置信度和核验说明。该文件用于补充旧法规正文没有明确记载失效信息的情形。

置信度反映证据完整程度，不代表独立法律意见；高风险或对时点敏感的使用场景
仍应回到记录中的官方来源核验。

## SQLite 索引

`db.sqlite3` 是由公开文本生成的轻量目录索引，核心表为 `law` 和 `category`。
它适合按标题、层级、状态和日期做快速筛选：

```bash
sqlite3 db.sqlite3 <<'SQL'
.headers on
.mode column
SELECT name, level, publish, valid_from, status
FROM law
WHERE name LIKE '%公路法%'
ORDER BY publish;
SQL
```

SQLite 是派生索引，Markdown 和公开元数据才是阅读、核验版本与追溯证据的
主要入口。不要仅凭数据库中的一个状态字段判断具体案件时点的法律适用。

## 获取数据

```bash
git clone https://github.com/Theonefkguy/Chinese-Laws.git
cd Chinese-Laws
```

法律文本可直接作为 Markdown 语料处理；JSONL 文件适合流式读取，SQLite
适合本地快速查询。

## 来源与可靠性

主要来源包括国家法律法规数据库、全国人大及其常委会、国务院及各部委、
最高人民法院、最高人民检察院和地方国家机关网站。对于官方历史页面已经
缺失的旧文件，仓库可能采用政府或法院转载、法院法规库等可信二级来源，
并尽可能保留来源等级、哈希、条数校验和生命周期证据。

来源可访问不等于当前有效，正文一致也不等于案件时点适用。处理现行法、
历史版本或高风险法律问题时，请以相应国家机关的正式发布和最新有效性信息
为准。

## 更新机制

本仓库是生成式公开镜像，不在这里运行采集、清洗和核验代码。维护端完成文本
整理、来源核验、生命周期审定、索引重建和质量检查后，每日定时检查是否需要
同步：

1. 只接受已经提交且工作树干净的源数据；
2. 只同步公开白名单中的法律文本、SQLite 和元数据；
3. 推送前执行差异上限、路径白名单和 SQLite 完整性校验；
4. 没有变化时不创建空提交；
5. 异常大批次或校验失败时停止自动发布，等待人工检查。

每个自动发布提交都记录 `Source-Laws-Commit`，便于维护者从公开快照回溯其
源数据版本。

## 反馈错误

发现正文残缺、OCR 错误、版本缺失、日期错误或效力状态存疑时，请提交 Issue，
并尽量附上：

- 法规完整标题和涉及版本；
- 仓库内文件路径；
- 具体错误位置；
- 可核验的官方来源或可信转载链接。

由于法律文本属于自动生成镜像，直接修改数据文件的 Pull Request 可能在下次
同步时被覆盖。建议先通过 Issue 提交证据，由维护端修正源数据后统一发布。
